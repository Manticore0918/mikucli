# Full-Screen Terminal UI and Immediate Task Cancellation

mikucli will use a `prompt-toolkit` full-screen Terminal UI by default for interactive TTY sessions. The renderer owns the terminal while active: a capped, scrollable Activity View occupies the main region; a persistent Session Status and any pending Tool Approval appear above a bottom-anchored Input Composer. Non-TTY and single-task invocations remain inline. `/tui fullscreen` and `/tui inline` switch the current interactive session only, while `--no-tui` provides a per-launch escape hatch and failed full-screen initialization falls back to inline mode with a warning.

The Activity View retains the newest 10,000 rendered lines and sends users to the Run Log for older output. It auto-follows new activity only while positioned at the bottom and supports mouse-wheel and `PgUp`/`PgDn` navigation. The Input Composer grows from one to eight lines, preserves pasted newlines, submits with `Enter`, and inserts a newline with `Alt+Enter`. While an agent task is active it accepts only `/stop`, `/eval stop`, and a pending approval response; ordinary Task Prompts and other Slash Commands are accepted only while idle. A pending approval is displayed above the unchanged `You:` input, which accepts `y`, `n`, or `/stop`.

Task Stop is an immediate cancellation contract. `/stop` and busy-state `Ctrl+C` return the Terminal UI to idle within about one second, terminate an active tool process, cancel an in-flight model request, discard any late result, and prevent the cancelled task from launching another tool. Idle-state `Ctrl+C` clears the draft; `/exit` and idle `Ctrl+D` perform Session Exit. Model calls will therefore move from blocking `urllib` requests to an async cancellable HTTP client, with cancellation propagated through the agent runtime instead of detaching an uninterruptible worker thread.

Agent work and a background eval may remain active at the same time, and Session Status shows both states, including eval completion and parallelism. `/stop` targets the foreground agent task first and otherwise targets the eval; `/eval stop` always targets the eval explicitly. If Session Exit occurs while an eval is active, mikucli stops it, waits for its partial report, restores the terminal, and then exits.

This design replaces the current `PromptSession` plus `patch_stdout` redraw behavior because that approach keeps input available but cannot keep it at a stable viewport location. It also rejects an unbounded in-memory activity buffer, persistent renderer selection, a second TUI framework, and logical cancellation that leaves blocking model requests alive. The consequence is that interactive output must flow through renderer events instead of direct `print()` calls, the provider/runtime boundary becomes cancellation-aware, and PTY-level tests are required in addition to state and unit tests. Inline output remains available for redirected streams, automation, unsupported terminals, and recovery.
